      What is an .ics file?

      An .ics file (also called iCalendar, defined by RFC 5545) is a plain-text format for calendar data. Google Calendar, Apple Calendar, Outlook and most scheduling services export events in it, which is why an invitation you receive by email often arrives as an attachment ending in .ics. Inside, one VCALENDAR block holds a list of VEVENT blocks, and each event lists properties such as SUMMARY, DTSTART, DTEND, LOCATION and DESCRIPTION.

      If you only need to look inside one — an invitation a colleague sent, a calendar exported from an old phone — an .ics viewer online saves you from importing it into a calendar first and leaving a mess behind. The format is text, so it can also be edited and re-imported — but it has rules that are easy to break. Values are escaped with backslashes, long lines are folded every 75 octets, dates can be plain dates, local times, times with a time zone ID or UTC, and a repeating event is stored once with an RRULE rather than as a hundred copies. Opening the file in the viewer shows how a calendar app will read it, and the validation report points at the parts that might import badly.

      Questions people ask before using it

      Is my calendar file uploaded to a server?

      No. The file is read with the browser's own file API and parsed in memory on this page. Nothing is sent to a server, stored or logged, and the tool keeps working if you go offline after the page has loaded.

      How do I open an .ics file?

      Drop the file onto the box above, choose it from your device, or paste the file's text. Every event appears in a table with its start and end time, location, description, organiser and recurrence rule.

      How do I convert an .ics file to CSV or Excel?

      Load the file, then press Download CSV. The file is written with UTF-8 and an optional byte-order mark, so Excel opens accented characters and non-Latin text correctly. Each event becomes one row with start, end, UTC times, time zone, summary, location and description.

      Which iCalendar properties are supported?

      VEVENT properties including SUMMARY, DTSTART, DTEND, DURATION, LOCATION, DESCRIPTION, ORGANIZER, ATTENDEE, STATUS, RRULE, CATEGORIES, URL and UID are read, together with the calendar's VERSION, PRODID and CALSCALE. Date values with a time zone, UTC values, all-day dates, folded lines and escaped characters are handled.

      Why does a validator show warnings for a file that works?

      Calendar apps are forgiving, so a file can open everywhere and still break the specification. Missing UID or DTSTAMP values, lines longer than 75 octets and unknown time zone IDs are common warnings that can cause duplicates or wrong times after an import.

      Does this work on a phone?

      Yes. The layout switches to a card list on narrow screens, and the export buttons work the same way in mobile Safari and Chrome.
